# Receiving Code Review

When receiving code review feedback, before implementing suggestions, approach with technical rigor and verification — not performative agreement or blind implementation.

## Process

1. **Read carefully** — understand what the reviewer is actually saying
2. **Verify claims** — is the feedback technically correct? Test it
3. **Ask clarifying questions** — if feedback seems unclear, don't guess
4. **Make changes thoughtfully** — don't blindly accept every suggestion
5. **Explain your reasoning** — especially when pushing back

## Anti-Patterns

- "OK I'll fix it" without understanding why
- Accepting every suggestion to avoid conflict
- Dismissing feedback without investigation
- Making changes without re-running tests
