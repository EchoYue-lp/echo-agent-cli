# 任务运行历史与详情

侧栏“新建任务”创建普通 Conversation；“最近任务”同时呈现普通会话和 IM／cron 的原
TaskRun。上下文面板的“运行历史”读取当前工作空间的正式 TaskRun。普通轻量聊天回合
沿原可见性规则，IM／cron 运行即使无计划、失败或取消也可见；不能把“没有计划”或
“没有 transcript”解释成没有运行。打开任何历史入口都不会创建任务、计划或运行。

## 发现与选择

运行列表每页最多 20 项，沿后端提供的 continuation 继续，按创建时间和 run_id 降序稳定排列。筛选和刷新从第一页重新开始，后端将续页绑定到工作空间、产品数据 generation、筛选和页大小；这不是多页事务快照。页间状态或计划变化可能改变行的可见性；新插入在原上界之前的运行要刷新后查看，不以 updated_at 的变化重排旧行。

列表读取失败保留已显示页及错误，不把部分集合当作完整空列表；界面只报告本页数量，不虚构总数。没有后续位置的“更多”调用是无操作，不取消正在读取的第一页。服务端保留的候选和传输有界，但目录枚举、authority 恢复仍可能扫描整个运行集合，不能据此宣称已有索引或常量查询性能。

点击历史行后，详情、刷新、事件页和原控制均绑定所选 run_id 与捕获的工作空间 generation。同会话产生了新的 latest 运行也不替换历史选择。“当前会话运行”才显式返回实时会话视图。旧作用域或旧访问的迟到成功、失败及 busy 结算不能覆盖新目标。

### 从最近任务或定时运行历史打开

侧栏保留同一 IM 会话的不同 Run，已有 Run 行时不再重复显示对应会话行。定时任务页的
“查看任务结果”定位已读日志中的原 Run，确认工作空间后打开聊天中的任务详情面板。
两个入口都使用同一个精确历史选择，不用当前会话 latest 或聊天态刷新替代所选运行。

会话元数据确认 transcript 存在时才读取会话；运行早于消息落盘失败时，直接读取原
Run 的状态与事件，不补造会话。定时历史“查看任务结果”会检查本次会话载入结果及原 Run
快照；必要读取失败时保留错误，不继续打开任务详情或关闭设置页。目标会话本来已经激活，
也不能以保留的旧页面当作本次读取成功。旧 Failed 记录及错误正文保持原样，不通过重新
执行修补历史。

侧栏最近任务目前尚有独立源码缺口：它未消费会话载入失败的返回值，Run 读取失败后也
可能沿保留的旧选择继续打开面板。因此上述失败后停止导航的保证仅适用于定时历史入口，
不能扩展到侧栏；侧栏须补失败路径保护和回归后再验收。

## 计划、Goal 与报告来源

详情复用后端 TaskRun、PlanTask、SubagentRun、产物和原操作回执；PlanTask 仍按每页 20 项呈现，原详情 Modal、搜索、筛选和键盘焦点继续保留。未知进度和时间显示未知，执行完成与计划任务提交完成分别表示。

运行目标与 composer 使用同一个 canonical Goal；普通 Steer 由主模型理解，不自动改 Goal。现有用户显式 Goal 控制继续沿原 revision/CAS／安全点处理，列表不新增写入口、队列或 Goal 权威。旧计划没有绑定当前 Goal revision/hash 时，仍可作为历史查看，但不计当前目标进度。

完成报告来自后端原 completion gate。独立查询可能跨越 Goal 或计划提交，因此界面在显示“通过”前核对原 run_id、Goal revision、plan revision 以及计划的 Goal 绑定。版本不匹配时明确显示需刷新，不将旧通过标记复用于当前目标；后端当前版本报告的原阻塞与失败不被隐藏。这是呈现资格核对，不新增验收执行器，也不从当前 Todo 或最后一个 Subagent 推算 TaskRun 成功。

## 事件与操作回执

执行记录沿原 journal 的 after_sequence 和 limit 分页，每次最多 256 项，精确保留字符串序号与 has_more。存在未读页时，界面提示详情可能不完整；缺口、错 run、坏 cursor 或恢复错误保持明确错误与已知位置，不用空结果冒完整。前端最多保留 500 条事件只限制内存，不代替服务端分页或原 journal，也不表示早期记录已从磁盘删除。

暂停、取消、继续与重试消费原 typed receipt。accepted/no-op/rejected 与物理执行停止、运行终态分别呈现。任务重试还核回执的 task_id；A→B→A 即使身份文字相同，也属于新的面板访问，第一回访问尚未返回的回执不能覆盖新请求。原执行仍由后端 owner 结算，关闭详情或停止观察不表示已取消底层工作。用户修改 Goal 已获得成功 CAS 回执时，同一工作空间 generation 和 run 的规范目标仍须立即更新；浏览切换不能丢弃已提交的目标事实，旧失败或普通操作不获这一例外。

## 验收边界

本指南按 CLI `5132d6b` 的实际入口更新；本轮只校对文档，不重新运行产品程序或测试。
历史 jsdom／类型检查、Rust 查询／journal／IPC 和原生人工结果各自保留输入与覆盖范围，
不能互相替代。列表性能须用原 TaskRevisionService/PlanValidator 接受并冻结的数据，
区分 1/10/50/100 个合法 PlanTask、10/100/1000 个运行与独立 10k/100k 事件历史；本页不承诺性能收益。

最终新版的精确待验是：从侧栏和定时历史分别打开原无 transcript／无计划 Failed Run，
确认显示相同 run_id、工作空间、Failed 状态和错误；打开一个有 transcript 的原 Run，
确认会话与详情身份一致；切到另一运行后返回，确认旧请求没有替换新选择。
读取失败时只核错误与原页面保留，不要求用户修改配置、授权凭据或重放失败任务。

浅深主题、常用／最小窗口、加载／空／错／长 Unicode 标题、键盘与高数据量的真实 Tauri/WebView 验收仍需具名制品。浏览器或 jsdom 不替代原生视觉，普通构建也不证明用户当前窗口已更新。本改动不涉及 Framework/SDK 公共 API，原 examples 不需增加平行任务示例；官网待最终合格 EKO 来源统一同步，未部署状态不变。
