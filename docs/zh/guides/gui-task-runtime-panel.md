# GUI 任务列表与详情

会话的任务入口打开右侧上下文面板。面板显示当前会话已加载的 TaskRun，并沿用原 TaskRuntime 查询、文件记录与事件投影；普通聊天 turn 不会因为打开面板而变成任务。它不是所有历史任务的独立目录，也没有新增任务存储或服务端分页协议。

## 阅读任务状态

顶部展示目标、原运行状态、触发模式和最近更新时间。“已提交完成”统计 Todo 投影中已完成的任务；“执行完成”同时考虑对应 Subagent 的成功完成记录。Subagent 执行结束而任务仍在评审或收尾时，列表明确显示这一区别。任务尚未展开时显示进度待记录，不推算完成百分比。

执行计划支持按状态筛选，以及按标题、任务编号或负责人搜索。每页最多呈现 20 张卡片；筛选与分页只处理已经加载的投影，不改变后端查询或任务图。需要关注的恢复原因与原任务摘要显示在卡片中，长标题在详情里完整呈现。该呈现上限不构成高数据量性能基准通过的结论。

点击卡片可查看描述、前置任务、验收标准、文件、任务产物、尝试次数、时间和运行身份。已有 Subagent 记录时，可进入原 Subagent 详情。TaskRun、PlanTask、SubagentRun 分别保留各自身份，不以界面卡片复制运行状态。运行路由保留在详情的运行身份中，作为原记录的诊断信息，不将它当作 GUI、IM 或 cron 的来源证明。

## 修改与操作

暂停、取消、继续、重试、编辑标题、跳过和新增任务均复用原 `taskRuntimeStore` 操作。任务详情使用共享 Modal，支持焦点约束、Escape 关闭与返回原触发控件；关闭详情不会批准、取消或跳过任务。

编辑标题在详情内完成；失败时保留草稿和原错误。跳过任务需要明确确认，Goal 验收仍按原验收记录处理。重试继续受原任务状态、运行状态和次数限制；后台更新使任务不再可编辑时，已有编辑或跳过确认不能继续提交。

操作等待期间禁止重复提交，界面显示请求处理中。接口返回后，回执只报告请求已返回及原运行记录中的当前状态；不会将按钮点击视作执行结束、取消已物理结算或验收通过。读取或提交错误直接可见，状态权威仍属于后端。

“运行控制与验收”保留原目标修改、预算、恢复结算、Goal 验收与用量查看能力。列表、详情与回执支持既有深浅主题和窄窗口，不增加依赖。
