# GUI 任务列表与详情

任务入口打开原右侧上下文面板。“运行历史”按有限页列出当前 Workspace 的正式 TaskRun，区别于侧栏普通新建/最近任务会话。选择历史行查看该精确 run；“当前会话运行”显式返回跟随当前会话。普通聊天 turn 不会因打开历史成为任务，也没有新增任务 store。

最近任务默认展开，点击标题可收起或再次展开；这只切换列表显示，已打开任务、当前工作空间及已加载内容保持。折叠不会重新发起列表请求。

## 助手消息与完整回复

助手进度、部分回答、独立思考、工具和运行状态按其真实来源呈现。进度与最终回答即使
正文相同，也可能是两条独立消息；只有能证明属于同一个最终候选时才合并显示。思考可
单独展开，签名和加密原件不会转成聊天正文，工具保留实际先后顺序。

运行时，两段公开正文之间连续出现的思考与工具调用合并为一行中间过程摘要，点击可展开
原顺序的全部过程，再次点击收起；新工具和思考继续追加到原分组，不重复堆叠摘要行。
失败、取消或状态未恢复的工具在折叠行保留明确提示。

归属明确的子代理也在对应过程行内展开；缺少原父运行或日志位置时显示未恢复提示，
不把它猜作最近一条回复的过程。图表和原始图表数据保留在最终答案之外；查看来源会话的
子代理只展示来源摘要，完整日志须打开原会话，避免把来源运行当成目标会话的操作对象。

收到原运行时确认的最终回答后，本轮的进度正文、思考、工具和 Subagent 过程默认整体
收起为“执行过程”，最终答案独立显示；用户仍可反复展开和折叠。仅出现候选块、生成结束、
失败或取消不会假装已经发布最终结果。失败原因和会话保存告警仍保持在过程之外可见。

运行时确认最终回答的事件与回调继续保留。出现文字、一段生成结束或保存成功都不能
单独代表完整回复或整个任务完成；分叉入口仍受原执行和完整回复资格约束。迟到的工具
批次观测不能把已完成、失败或取消的运行重新变成等待中。重新生成后续回复时，之前
消息的工具顺序继续保留。

开发期不再承诺旧消息格式的运行时兼容，新格式自身的冷加载、重载、Fork 和恢复仍须
工作，旧原件／失败与恢复材料仍保留。本节不把已保存的前端测试当作真实后端 DTO 桥
或新版桌面验收。数据与验证边界见 [ADR 0057](../adr/0057-native-messages-and-progress-policy.md)。

### 紧凑输入区与运行统计

工作空间、权限、思考深度、模型、附件及发送/停止位于输入框内部；框外统计行可展开明细。
窄屏仍保留一行主统计和上下文指示器；点击统计行展开完整口径和原日志覆盖情况，不额外拉高输入区。
上下文圆环可通过 Tab 聚焦后按 Enter 或点击查看容量与来源，按 Escape、再次点击或移开焦点关闭详情。
主行展示目标会话主链轮数/步骤、最近合格的客户端观测速率、实际已报告累计 tokens、
按输入量加权的缓存率及当前上下文。正在请求时速度标“上次”，缺少同口径计时显示 `--`；
单包和整个请求耗时不冒充生成速度。累计与当前上下文分别显示，草稿估算不入累计。

主链、Subagent 和未覆盖的标题/压缩等辅助调用分别说明；重试费用保留，重复回放不重复收费。
缓存写入不算命中，失败已报告用量仍累计；漏报、尚未返回、身份不全、冲突或原日志前缀不全
会明确显示。切换历史后从原日志检查点与后缀恢复，超过回放尾窗也不清零；没有可信前缀就不
声称全量。编辑、回退或清空前台不冲销费用，Fork 继承前缀不算目标会话实际调用。
详细边界见 [ADR 0066](../adr/0066-turn-presentation-and-usage-projection.md)。

### 长操作与 60 秒提醒

聊天下方的“当前执行状态”展示真实模型／工具操作、“已用时”和“最后事件”。等待时耗时
继续增加，最后事件只随真实事件推进；计时器不会写助手正文、补新发现或宣布完成。
运行结束或切换历史后，该瞬时等待状态清除。

60 秒是原模型请求安全点的提醒阈值，不是每 60 秒保证收到一条回答。超过阈值仍未发布
公开自然语言报告时，系统在下一次既有模型请求前提醒一次；长工具尚未返回时继续显示
真实操作，不额外请求模型或打断工具。公开报告后重新计时，Reasoning、工具日志和状态
不充当自然语言报告。具体边界见 [进度策略](../adr/0057-native-messages-and-progress-policy.md)。

## 阅读任务状态

顶部展示目标、原运行状态、触发模式和最近更新时间。“已提交完成”统计 Todo 投影中已完成的任务；“执行完成”同时考虑对应 Subagent 的成功完成记录。Subagent 执行结束而任务仍在评审或收尾时，列表明确显示这一区别。任务尚未展开时显示进度待记录，不推算完成百分比。

这些统计仅用于 Goal revision 和摘要都匹配当前目标的计划。目标修改后，旧计划、Todo 和
Subagent 结果仍保留为历史；主区域明确提示尚未绑定当前 Goal，旧完成项不计入当前目标
进度，列表使用历史状态标记。晚到的旧 Subagent 完成事件不能恢复当前完成计数；原计划
经后端重新绑定后，才按规范 Todo 和执行记录恢复统计。这不是删除历史或改变任务状态。

执行计划支持按状态筛选，以及按标题、任务编号或负责人搜索。每页最多呈现 20 张卡片；筛选与分页只处理已经加载的投影，不改变后端查询或任务图。需要关注的恢复原因与原任务摘要显示在卡片中，长标题在详情里完整呈现。该呈现上限不构成高数据量性能基准通过的结论。

点击卡片可查看描述、前置任务、验收标准、文件、任务产物、尝试次数、时间和运行身份。已有 Subagent 记录时，可进入原 Subagent 详情。TaskRun、PlanTask、SubagentRun 分别保留各自身份，不以界面卡片复制运行状态。运行路由保留在详情的运行身份中，作为原记录的诊断信息，不将它当作 GUI、IM 或 cron 的来源证明。

## 修改与操作

暂停、取消、继续、重试、编辑标题、跳过和新增任务均复用原 `taskRuntimeStore` 操作。任务详情使用共享 Modal，支持焦点约束、Escape 关闭与返回原触发控件；关闭详情不会批准、取消或跳过任务。

编辑标题在详情内完成；失败时保留草稿和原错误。跳过任务需要明确确认，Goal 验收仍按原验收记录处理。重试继续受原任务状态、运行状态和次数限制；后台更新使任务不再可编辑时，已有编辑或跳过确认不能继续提交。

操作等待期间禁止重复提交，界面显示请求处理中。接口返回后，原类型化回执区分已接受请求、no-op 与重试路径，并展示原运行记录的当前状态；不会将按钮点击视作执行结束、取消已物理结算或验收通过。读取或提交错误直接可见，状态权威仍属于后端。

“运行控制与验收”保留原目标修改、预算、恢复结算、Goal 验收与用量查看能力。列表、详情与回执支持既有深浅主题和窄窗口，不增加依赖。

## 定时运行与微信结果通知

定时任务页的通知设置与任务执行状态分开。设置绑定原 task definition，发送给已连接微信的扫码本人；需要先从手机发过单聊，保留其明确 context reference。改设置只影响之后准入的 occurrence，不能把已运行任务重绑到当前页面项目或新登录账号。

定时历史中只有解析到原 run 身份的记录才查询该 run 的通知。任务完成、通知已准入、发送已开始、微信 Accepted/Rejected/Unknown 是独立事实；界面显示“微信已接受结果通知”不代表手机收件或已读。无通知的 run 不补猜目的地。结果来自原 TaskRuntime 任务结果及产物引用，不以 webhook 的 finished 摘要代替。通知失败不重跑原任务；Unknown 提示不要直接重发。

这些入口不新增定时通知 store。微信排队回复由原 pump route 保存数据，claim 后原 owner
驱动输出。已有具名手机微信回复／历史、Cron 创建与手动运行／历史的有限人工成功；这些
结果不代表新版自动 Cron、结果通知、HITL、排队压力或最终 main CI 已通过。新版仍须单独
验证自动触发和禁用，旧 errno63 Failed 记录保持原样，不改写或重放来补成功。
见 [个人微信配置](../configuration.md) 与 [ADR 0056](../adr/0056-personal-weixin-channel.md)。

## 运行页与事件页

运行按创建时间和 run_id 排序，状态筛选变化或刷新重新开始实时查询；continuation 不承诺事务快照。错误保留已显示页并允许显式重试，只有原 continuation 存在时展示下一页，不虚构总数。执行记录按有限页读取，“继续读取执行记录”沿原 sequence 读取未完尾部，明细尚不完整时保持提示。这些数量边界不等于高数据量或原生性能验收通过。

历史详情与当前聊天是分开的呈现。查看旧失败不会把当前聊天改成失败；当前聊天的 Continue 提示与进度仍属于原运行。

任务控制同时绑定捕获的工作空间代次和所选运行。项目位置已被替换时，旧动作会被拒绝，需要重新载入当前运行后再操作。历史列表选中当前运行后，聊天进入新运行也不会替换已选详情。

### Steer 与 Goal 控制

输入框上方展示持久化的 Steer 队列。编辑排队项使用同一 journal CAS：`input_id` 和队列位置保持不变，revision 递增；已经执行或 revision 过期的项会被拒绝。列表显示权威阶段和送达状态；安全点尝试还会在同一输入行显示“已保留”或“已拒绝”，不改变后端权威。Goal 编辑复用原 TaskRuntime Goal revision/CAS。运行中保存会先请求暂停，再显示安全点等待和提交确认进度。界面读取规范的 Paused 状态及可见工作，物理执行是否已结算仍由后端 CAS 校验；只有明确的活动执行拒绝才在 30 秒观察上限内继续等待。版本冲突、读取失败或更新被拒绝都会保留草稿并显示错误。只有读到新的规范目标内容及下一 revision，界面才显示更新成功；保存不会自动恢复运行。结束 Goal 仍调用既有取消路径，区分请求已接受与规范运行已取消，不会写入空 Goal。

普通 Steer 交主模型结合历史理解，不能自动替换已有 Goal。用户在“当前目标”点击“编辑”、
填写目标和原因后保存；等待超时表示本次观察结束，暂停请求仍有效，目标尚未确认更新，
应保留草稿并重新核对版本。不要为消除等待提示而重复创建任务或把目标改成空字符串。

### 压缩与重开后的完整目标

Goal 与原始输入来源来自原 TaskRuntime journal；恢复摘要或最近四条预览不代表完整历史。
长 Goal 和被省略的早期输入通过本机产品数据中的原文引用及 `read_artifact` 分页读取，
不能把文件存在、聊天预览或“已接纳”当成模型已经读完或执行完成。已有 Goal 的用户
revision／SHA 与原输入来源分别保留，普通恢复不创建新 Goal 或重放副作用。

必要原文缺失或校验失败时，原运行保留 Goal 和恢复状态并暂停相关工作；修复可读性后
通过原运行的恢复入口继续。不要切换到更宽的工具权限、重新发送旧输入或覆盖历史来绕过。
应用资料与产品文件由系统恢复，用户无需在聊天中粘贴 Auth、配置文件、密钥或内部路径。

### 轮次收尾与整个目标完成

启用续接的长任务在自然结束一轮回复时，模型会收到提示，要求简短对照用户总 Goal 说明：本轮推进了哪项
原目标义务、实际证据及其验证层级、仍未完成的义务、当前障碍（若有）和下一步。它允许
写成一段话，不要求机械的五段标题；用户明确指定的报告格式仍可使用标题。本轮没有新增
验收证据（例如只整理了材料）时，提示要求明确说明，材料整理、测试通过、原生操作与发布
状态互不冒充。实际模型是否遵循这些要求需要单独验收。

这里区分“本轮回复自然结束”和“整个目标完成”：前者只是有限轮次收尾，助手写出“完成”
或总结缺项都不会改变运行终态，完成门禁、取消、预算和重复阻塞规则仍由运行时决定。
普通闲聊与未启用续接的对话不套用这套固定收尾模板。

总 Goal 对模型只读：模型的执行重点、计划或总结不会改动目标原文、revision 或 hash；
只有用户在“当前目标”显式修改才沿原 revision/CAS 生成新版本并保留历史原文。该收尾
说明属于模型行为提示策略，不保证每个模型必然遵循同样格式，也不能当作完成回执。
见 [上下文压缩与恢复策略](../adr/0048-context-compression-product-policy.md)。

## 验证边界

本指南按 CLI `5132d6b` 的既有实现对账，沿用 [任务状态权威](../adr/0015-task-graph-status-authority.md)
与 [有界查询投影](../adr/0008-taskruntime-bounded-query-projections.md)。文档修正没有改动
运行机制、Framework 或 SDK API，也没有在本轮重新执行测试、编译或真人操作。
已有测试定义和各批历史通过只支持对应输入，不能替代最终组合的新版桌面验收。

组件截图使用明确标注的合成任务数据，只证明实际 React 界面的布局与交互。完整性能基准、原生桌面窗口、真实 IM/cron 触发和最终 main 集成验收分别记录，不能由截图替代。本次不修改 API 示例；官网继续描述已交付主线能力，未合并的视觉改动不提前对外宣告。

最终新版仍需具名记录这些操作：运行长工具超过 60 秒时对照耗时／最后事件及后继安全点
报告；修改 Goal 后确认 revision 递增、旧计划不计当前进度；保存后冷重开同一运行并读取
早期完整输入和长目标末尾；切换工作空间或历史时确认迟到响应不改新页面。
GUI 的主题、窄窗口、键盘／焦点、附件、真实工具错误、HITL 和 Subagent 详情也须分别
验收。没有对应原件时保持“待验”，不把当前窗口、构建成功或这份指南当作通过。

Goal 控制绑定当前工作空间、会话、工作空间代次和运行。离开该视图会退役原界面观察，迟到结果不能清除另一目标的草稿或忙碌状态，即使随后回到同一运行。Steer 编辑也会保留失败草稿，并拒绝内容身份已变化的输入。IM 渠道拥有的输入显示“渠道处理”，在此 GUI 队列中禁用拖拽、编辑、执行和删除。

同一目标仍可能有先载入、后刷新：规范刷新已提交后，先前载入的旧 Goal、验收和事件游标
不能再覆盖它，历史详情与当前聊天各自保留原作用域和代次。这条退役判断只比较同一运行：
聊天开始载入新 run 时，旧 run 的刷新或迟到 Goal 回执不会吞掉新目标；历史详情仍固定
查看原选择，显式选择另一 run 后也能完成它的载入。纯读取刷新失败且目标未改变时，
尚可用的初始载入仍可结算；Goal CAS 成功则先消费后端真实 TaskRun 回执，后续刷新失败
保留错误和旧计划的历史状态，不能借旧载入恢复 r1。已读到的更高 Goal／计划版本不会被
迟到的旧回执覆盖，不依赖更新时间猜新旧。同 run 的两份现有视图同步规范字段，各自保留
事件页游标；后续成功的规范读取会清除两份匹配视图的读取错误。载入和轮询由当前目标
结算，旧请求不能解除新目标的忙碌状态。

Steer 编辑框支持 Enter 保存、Escape 退出编辑；输入法组合期间不触发这些快捷键，确认中文或日文候选词不会提前提交未完成的编辑。

Steer 排序既可拖拽，也可用 Tab 聚焦每行“上移／下移”按钮后按 Enter 或空格操作。按钮调用同一持久队列排序入口，不先修改前端数组；首尾、正在处理的操作及相邻渠道输入会禁用对应方向，结果和冲突仍由原队列 revision/CAS 判定。

三种项目来源的工作空间创建弹窗也保护名称框的 Enter：确认输入法候选词不会触发创建或切换工作空间。

立即执行未成功时只提示尚未确认送达；重试前应查看同一输入行的原保留、拒绝状态及错误，不能仅凭该返回值认定正在等待安全点。
