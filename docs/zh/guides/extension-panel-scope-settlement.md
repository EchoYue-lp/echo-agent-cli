# 扩展面板的工作空间切换与回执

Hooks 面板中的列表、重新加载和匹配检查都属于发起操作时的工作空间及其数据代次。切换工作空间或重建同一工作空间后，面板展示新目标的实际结果；旧目标迟到的成功、错误及等待结束不会覆盖当前列表或提示，也不会自动再次查询旧目标。

从甲切到乙再回到甲，会开始一次新的面板访问。第一次甲访问的未完成请求仍属于旧访问，不能覆盖重新进入甲后的结果。卸载面板同样停止消费其回执。

切换页面只改变当前界面接收哪些结果。已经开始的后端重新加载仍由原运行时负责结算，界面不会把丢弃旧显示回执称作取消成功。回到相应工作空间时，可重新读取实际配置。

Hook 事件目录读取与规则列表读取分别反馈错误。事件目录读取失败时，规则列表成功不会抹去该错误；页面提供“重新加载事件”，只重新读取事件名称，不重新加载配置、不执行 Hook，也不自动开始匹配检查。重读成功后使用返回的真实事件选择继续原 dry-run；重读失败保留错误和现有列表。事件读取同样沿当前面板访问及代次结算，旧访问的迟到结果不能覆盖新目标。

匹配检查沿现有 dry-run 入口，只显示规则匹配结果，不执行 Hook，不签发工具批准。真实 Ask/HITL 的输入、审批、取消、超时与执行结算继续由既有权限和运行时链路处理。

本次修复不改变扩展 API、默认权限、插件激活或持久配置，也不新增任务状态、执行器或存储。它只修复 Hook 专属面板的迟到结果归属和事件目录读取失败后的恢复；其它扩展面板的覆盖另行核验。
