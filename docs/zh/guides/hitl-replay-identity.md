# HITL 回放中的请求与释放身份

HITL 的 `request_id` 是可复用的关联标识；每次实际请求的 `response_target` 和原工作空间、会话、root Turn、活动 Turn 等坐标共同确定回复归属。GUI 的列表和弹窗只投影这份原始身份，不创建另一套请求或审批状态。

实时事件和 journal 回放使用同一入口。审批、补充信息、选项以及请求释放事件，都须保持外层事件的工作空间、会话和 Turn 与 HITL 身份一致。框架或适配层产生不一致事件时，当前界面保留原待答请求，不能用错误释放事件把它移除，也不推进当前操作的最后事件时间。

同一请求 ID 在恢复后可以有新的回复目标。旧目标的迟到提交确认或释放只适用于旧身份，不移除新请求；重复释放不改变其它等待项。准确释放 FIFO 首项后，下一项继续显示其真实等待状态。

取消后仍可消费准确的释放事实以清理旧请求。释放事件本身不签发批准，也不把执行判为成功、失败或取消；执行终态仍由原运行时结算事件决定。页面关闭不自动同意，GUI 与 IM 的首答竞争、超时和后端清理仍由原 provider/dispatcher/owner 处理。

本修复只补齐已有事件身份一致性检查，防止内部错配回放破坏待答投影；不新增权限门控、持久化队列、状态机或执行器。真实 native、GUI/IM 同答和进程恢复资格须按各自验收记录确认。
