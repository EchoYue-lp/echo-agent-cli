# GUI 人工确认弹窗

EKO 将操作审批、补充输入和选项选择放在同一种人工确认弹窗中。顶部说明原请求所属会话与请求内容，操作参数和原请求编号可以展开查看。已有多个请求时，弹窗按现有队列顺序处理，并显示后续待办。

“稍后处理”、Escape 和点击遮罩只收起弹窗，不会批准、拒绝或取消任务。对话输入区上方保留待办入口；重新打开后，当前请求的输入草稿仍在。请求超时、被取消或已由其它入口处理时，展示跟随原请求队列更新，不在界面内推断最终结果。

审批中的“允许这次”“拒绝”“提出修改”与“本会话允许此工具”沿用既有答复范围。输入支持多行及中文，Enter 换行，⌘/Ctrl + Enter 提交；输入法组合过程中不会触发该快捷键。选择通过单选项和独立的提交按钮确认，补充说明为可选。

提交过程中按钮禁止重复操作。失败后保留回答供重试；提交成功仅表示答复已提交，不代表任务完成，也不宣称在 GUI/IM 同时回答时获胜。HumanLoop、请求身份和答复结算仍由原有运行时及 Tauri 回复路径负责。切换页面不会把答复发到新会话；原请求被替换后，新请求从空草稿开始。

本次仅改变 EKO 界面，不改变框架公共 API、SDK、工具、插件或示例。官网当前仅介绍产品能力，没有对应的弹窗操作手册，故无需同步网站。真实 Tauri 与 IM 并发答复验收由集成工作区负责，浏览器截图不替代该验收。
