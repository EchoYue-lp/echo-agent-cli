执行范围绑定 `docs/supreme/plans/2026-11-06T2300-免安装SSH运维/plan_01_SSH运维闭环.md`。全程使用现有 SSH 工作空间、shell、文件和 command cell，不部署 Eclip 远端服务。

## 前置条件与证据边界

- 使用用户指定或自有的 Linux/macOS 隔离目标。认证仍在原 GUI PTY 进行；口令、私钥内容和令牌不进入模型、命令、配置、日志或回执。
- 准备两类目录：远端 HOME/非 Git 目录用于日常运维；真实代码目录用于规则、目录扫描和搜索。代码目录可含较深层级和较大无关目录，记录实际规模。
- 只控制本次已明确授权的隔离服务、普通进程和容器；保留原启动方式、目录、配置、服务 unit、容器稳定 ID，以及恢复原状态的方法。没有可控制目标时，该项保持未执行。
- 记录源码清单、CLI/framework HEAD 加实际 WIP、App 主程序与资源摘要、OS 和连接 generation。旧运行包不得代替新冻结包；本地标准 SFTP stdio 夹具不得替代真实网络。
- 记录网络 RTT/丢包；ICMP 不通时保留探测失败，另记 SSH 命令往返样本，不能把后者写成纯网络 RTT。保持同目标、同目录、同模型、同网络条件比较；缺测项写 `unknown`。

## 时间和计数

分别保留输入提交、首个用户可见 Agent 状态、首个模型请求及最终结算时间。模型响应时间不归为 SSH 准备耗时；缺少模型请求时间证据时不能用首 token 倒推。

| 原日志事件 | 使用口径 |
| --- | --- |
| `agent project definitions prepared` | 工厂定义准备耗时，区分 `deferred_to_invocation` |
| `project file preparation settled` | 一次准备读取/关闭的耗时及 success；reused 表示提供者的只读会话，不是跨消息正文缓存 |
| `turn project context prepared` | 当前 turn 的项目准备总耗时，按 turn_id 配对 |
| `project SSH child spawned` | 按 connection_generation 区分 ordinary_sftp_spawns、preparation_sftp_spawns、streaming_sftp_spawns、execution_spawns；差值才是本次新增启动数 |
| `project SSH SFTP lane operation settled` | 普通池每次操作的复用与耗时；debug 日志可见 |
| `project SSH SFTP lane close observation started` | 记录 operations/opened/reused 和计划关闭的空闲 lane 数；这条日志不证明关闭成功 |

普通池容量 2 不包含准备会话、流式 reader 或业务命令。计数记录真实成功 spawn，包括随后初始化失败的 SFTP child；认证检查、主连接和交互 PTY 不属于业务命令数。冷消息可能先有工厂定义准备，再有 turn 准备，各用独立只读会话；不能要求整条消息所有通道增量小于等于 1，也不能假定准备通道已进入普通池。

每条消息保存其时间区间、原事件/工具结果和计数差值。并发连接或并发 turn 的数据不能混算；普通池的旧 open/reuse 汇总不替代四类启动统计。debug 日志按现有配置启用，不改全局权限或日志隐私边界。

## A：启动、规则与目标绑定

1. 在 GUI 测试登录并打开非 Git 目录，核对实际 host/user/port 和绝对远端目录；命令 `pwd` 与 SFTP 必须指向同一位置。缺连接、目标或目录变更应报错，不能回退本机。
2. 在代码目录分别记录新建 Agent 的冷消息和同一 Agent 的后续消息，至少各取 3 个自然样本。原“你好”场景单独保留，分别比较工厂准备、turn 准备和模型阶段；样本量小只能说明该条件下的结果。
3. 每次 invocation 的有效规则正文只读一次；同轮模型循环、Execute/reset 不重新准备。下一轮外部修改规则后必须读取新内容，包括同长度且保留旧 mtime、删除重建和坏 UTF-8；读取错误必须传播。
4. 同一连接连续执行 5 次普通只读文件操作。首次普通池为空时允许新开 1 条，后续健康、串行操作应复用；以实际 ordinary_sftp_spawns 差值和 lane_reused 配对判断。流式读取另外计数，不夹在该复用样本内。
5. 对同一已知结果做普通搜索、无 ERE 等价模式和大目录搜索，核对工具实际结果与原本地算法合同一致。回退仍是使用远端 FileSystem 的遍历算法，绝不是读取本机路径；记录实际读取/命令成本，不预设某个符号必然命中或某个忽略策略。
6. 在途任务中切换 GUI 焦点；关闭后重连；修改 SSH 别名解析到另一目标。原任务目标不能随焦点变化，重连必须重新核对实际身份，身份变化不能静默接管旧工作空间。

验收以消除重复准备和逐文件重开通道的直接证据为准，不预设首 token 必须几秒、固定倍数 RTT 或所有连接只开两条通道。保留每个真实样本和异常，不删除慢样本后只报告最好的一次。

## B：查询与启停闭环

| 场景 | 必须观察的结果 |
| --- | --- |
| 原三问：活跃进程、指定后端数量、指定服务健康 | 逐项给出目标、采样时间、计数口径和证据入口；区分服务副本/OS 进程/容器。证据足够后汇总，不自动扩展到数据库、cron 或修复 |
| 能力或权限不足 | 无 systemd、无 Docker、权限拒绝分别说明实际限制；不安装依赖，不把不可查询写成不存在 |
| 服务和容器启动/重启/停止 | 使用已有管理器；控制前核对 unit/归属或稳定容器 ID，控制后有界复查实际状态和健康。命令 exit0 不等于服务健康 |
| 普通进程启动或重启 | 使用明确的原启动方式、工作目录和必要配置；不能从 ps 猜环境，也不能把命令 cell 当成服务托管器 |
| 普通进程停止 | 核对原身份；同名候选、目标消失和 PID 复用负控不伤及其它进程。无可靠身份依据时说明无法安全自动停止，不用 killall/模糊 pkill 替代 |
| 重建容器/服务自动拉起 | 不把同名新容器当旧容器操作；停止后被管理器重新拉起时如实报告，不能宣称已持久停止 |

每步记录控制前状态、原命令/结果入口、命令受理或退出、控制后状态和未知项。健康检查失败但接口仍可响应可以同时成立。未取得工具/运行时证据不得补造业务结论。

## C：日志、故障与恢复

- 服务、普通文件和 Docker 日志默认最近 200 行，同时受原输出字节上限约束；验证时间范围/行数、stdout/stderr 和截断提示，不把整份日志灌入模型。
- 明确要求跟踪时采用有期限的读取/采样和原 command cell；停止跟踪只结束 Eclip 的读取，不停止被观察服务。完成后缓冲输出不得称实时流。
- 注入断线、控制响应丢失、超时、取消和复查超时。分别记录取消已请求、命令自然结束、远端看门狗到期、停止尚未确认；结束观察不等于用户服务停止。
- 控制结果未知时恢复原连接，先重新查目标状态；不自动重发 start/restart/stop。当前状态本身不能证明先前控制命令是否执行过。
- 关闭观察包括等待在途操作和原通道结算，使用同一有界期限。超时后原 child/reader/guards 继续保留，原 owner 可重新观察；不能清除 unknown 或把 `close observation started` 当成功。
- 失败后保留已批准发布的阶段发现、完成工具和原结果入口；运行状态与保存状态分别显示。重开历史后仍可见，不从工具日志合成未批准的发现，不自动重跑已完成工具。
- 关闭后的残留检查只针对已证明属于本次连接的资源。整台服务器可能有其它 SFTP 用户，禁止要求全机 `pgrep sftp-server` 为空或用 `pkill` 清理。归属无法核实时记录未知。

## 记录与交付

每个场景记录：源码/运行包身份，连接 generation，真实目标与目录，时间区间，四类启动数前后值，原工具/事件/日志入口，控制前后实际状态，预期与实测差异，最后确认保存位置，是否有结果未知的原操作，以及恢复方式。凭据和日志正文中的秘密先按既有策略处理。

源码回归、标准协议 stdio 夹具、真实 SSH、真实 GUI/模型、冻结 App 和精确 main CI 分别列结果；一项通过不能替代另一项。任何失败保留原件与自然退出，再修复并复验同一场景。只有整份当前 Plan 的验收覆盖后才能宣称免安装 SSH 运维闭环交付。
