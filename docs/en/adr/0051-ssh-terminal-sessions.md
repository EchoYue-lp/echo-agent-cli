# ADR 0051: Explicit SSH targets and original terminal session settlement

## Status

accepted

## Context

Approved Plan06 (plan:08c22af5-243e-4460-a70c-2c5e2ec186b6, SHA 7f0a96b913a019d2623283ea711f89a93daa2d60a1e86b4635f72797081624c0) continues from EKO 2b52251 and framework e4e5039. TerminalService already owns PTYs, but GUI creation precedes observation, tab/hide changes unmount observers, byte chunks are decoded separately, and close removes a session after clone_killer. In portable-pty 0.9.0, the Unix clone only sends SIGHUP; the original Child::kill adds forced termination after the HUP grace period. Original child wait and reader join remain necessary.

## Alternatives

1. System OpenSSH inside original create, ready frontend observers before creation, and retained original Session resources/settlement. Selected.
2. A new SSH library, daemon, executor/TaskRun, backend reserve/start or replay store. Outside the original terminal-only boundary; the approved project extension below adds a standard SFTP adapter without a second task/session authority.
3. Connected animation or shell prompt as login evidence, or kill return as Closed evidence. Rejected.

## Decision

System OpenSSH owns protocol, authentication, config, agent/key and host-key policy; portable-pty owns PTY/Child primitives. EKO TerminalService/TerminalSession remains the only session, target, admission and resource authority; Tauri only adapts. Framework, SDK pin, Agent ShellTool permissions and TaskRuntime do not change. Manual GUI connection does not authorize model execution; the model currently exposes no TerminalService tool.

Creation remains one existing create call. Target is local or structured ssh (host/alias, optional user/port), passed as independent system ssh argv. No shell command concatenation, unspecified-config override, weaker host-key option, credential storage, hardcoded server or local fallback. Spawn proves only a local process start.

A tab mounts xterm, output/exit/gap observers and bounded serial queues before create. All tabs remain mounted across selection/hide. Raw PTY Uint8Array goes directly to xterm; write callbacks release in-flight budget. Input is also serial and bounded. Real broadcast lag or overflow is visible and does not imply full history/VT replay. Every asynchronous setup step handles cancellation and cleans only its own instance. A dispatched create retains its original Promise; cancellation compensates the exact completed creation with close, retaining a retryable tab on failure.

The original Session retains the original Child, output reader JoinHandle and one settlement-task handle. Close requests settlement through original Child::kill/try_wait/wait and a real reader join. Only complete proof permits exact-instance removal and one exit event. Callers borrow the wait handle; cancellation or bounded observation timeout does not abort settlement or take an unfinished handle. Kill/wait/reader failures retain resources/target for retry and cannot publish normal Closed; retry cannot erase an irrecoverable reader error. Direct-child cleanup does not prove process-group or remote-side-effect termination.

The existing ApplicationLifecycleOwner synchronously closes terminal admission. close_all shares the creation boundary; incomplete terminal settlement retains the same application owner for retry. Event-bridge join is not PTY reader join. Actual id/pid/target and close values are reflected in manual TS contracts; invented cwd/created_at fields disappear.

## Consequences

Source/test preparation is not delivered runtime acceptance. This phase has no Cargo/native/remote lease. Rust, native windows, real authentication/remote interaction, full matrices and main/CI remain unverified until execution. An old GUI binary cannot qualify the new protocol. Only the coordinated acceptance phase uses the user's real target; product/test fixtures use generic targets.

The existing examples/lh6_product_soak.rs has no terminal/SSH consumer and needs no source migration. Any later example change must enter the original compilation chain. The coordinator mirrors only qualified exact sources to the website; no deployment here. Changed Rust inputs do not inherit the ace3 risk fingerprint automatically; later independently reassess the same exact six risks without acceptance expansion.

## Project connection extension

The user clarified that the sidebar task is a project: creation selects an existing local folder, a new local folder, or a remote project. The project-workspaces design and Plan `plan:986e9191-1a18-454b-a8b8-59ae18ad3bc7` supersede terminal-only acceptance for this extension. Workspace remains the project/location authority; TaskRun remains the execution authority. This ADR owns only the original terminal/SSH resource adaptation.

System OpenSSH runs a foreground authentication master in the original PTY. The GUI chooses its session id and subscribes before spawn, so initial password and host-key prompts are observable. Password input stays in this terminal, never project metadata, model context or logs. Authentication is checked using the real `ssh -O check` status; remote directory access uses SFTP canonicalization and metadata, not a prompt or local PathBuf lookup.

Each connection uses an application-owned private control socket and `ControlPersist=no`. Ordinary project terminals, structured execution and SFTP use that same socket. Slave calls set `ProxyCommand=false` and `BatchMode=yes`, including after the check/use race, to prevent a missing master from opening another connection. Host keys are not disabled. Draft creation transfers the same connection map entry to Workspace identity under the original service mutation boundary. Cancellation/close and transfer are serialized: an old draft cannot close an already-published project.

Before authentication, bounded system `ssh -G` output resolves hostname/account/port after native Host/Match evaluation. The original connection fixes those facts once and exposes them using the existing TerminalTarget shape; Workspace alone owns their persistence, location revision and resume comparison. The raw alias still selects its SSH config/IdentityFile/agent/ProxyJump behavior, while command-line HostName/User/Port and disabled repeat canonicalization pin the resolved destination. A config change between resolution and master spawn cannot replace A with B; literal percent characters in an already-resolved hostname are escaped before another HostName expansion. A later connection resolving differently requires an explicit project location decision, not silent resume. Configuration errors/timeouts do not start authentication, leak the full config to logs, or masquerade as a connected host.

Project authentication masters are not ordinary terminal tabs. A successful creation detaches its authentication renderer while the original service retains the master; normal project terminals are mux slaves whose close does not close the project. Failed creation explicitly closes its original draft owner. Project close stops new operations and observes active file/command/slave resources before closing only its own master. Original child wait failures retain the same child for retry. Application shutdown follows the existing lifecycle; it does not send a broad `ssh -O exit` against user-owned masters.

`openssh-sftp-client` implements the standard SFTP protocol over the owned system-SSH subsystem streams, without its optional `openssh` connection library. Version 0.15.10 was independently confirmed published, not yanked, MIT and MSRV 1.64 through the official registry API. Its future cancellation does not revoke a request already sent: original operation resources and read/flush/child settlement remain observed. Failed writes use the existing structured possible-side-effect/verify-before-retry contract; they must not be treated as definite non-writes by patch rollback. Atomic replacement requires the server's posix-rename capability. The original framework checkpoint format is reused through its location-bound adapter; an unavailable checkpoint is an error, never a fake non-Git result.

The existing SandboxExecutor adapter quotes actual remote cwd, environment and program arguments and reports plain SSH as isolation `none`. Local Seatbelt does not qualify a remote process. Unsupported remote isolation/resource restrictions are explicit capability errors. Cancellation and timeout do not kill a local SSH child and claim remote termination: the original physical execution and both pipes remain observed, and a known-complete command with uncertain effects keeps the existing typed failure. A lost remote-stop receipt remains nonterminal with its original resources. Buffered execution is not described as a live stream.

The original SandboxCommand runtime-only resource guards and cancellation token are carried into the same physical SSH operation before spawn. They are not serialized as a new wire contract. Failed wait retains the original child and those guards with the same connection; pending pipe joins are observed before close can succeed. The existing command-cell/Task owner provides bounded nonterminal cancellation observation; this adapter does not fabricate a terminal cancellation or create another execution owner.

Project terminals also receive the original host I/O lifetime guard before spawn, for both local and SSH targets. TerminalResources retains it until the original child and reader settle; cancelling the GUI observer cannot release it. This is an I/O lease, not an Agent/LLM slot. The existing application lifecycle must close/observe these terminals before waiting for the host I/O lifetime, preserving its original receipt and busy proof rather than waiting on itself.

After the existing begin_shutdown seals creation, close_interactive_sessions observes only the original human local/mux sessions and retains shared project authentication masters. The original lifecycle can then settle Agent/file work and use close_all to close idle masters. These methods share the same session map and child/reader settlement; they are not another terminal registry or shutdown state machine.

## Remote file CAS and bounded reads

The GUI's existing content revision contract uses a persistent sibling `.<filename>.lock`. Cooperating processes serialize the complete read/SHA-256 comparison and replacement through the same lock; ordinary atomic writes and external editors are not enrolled automatically. This is neither inode identity nor a transaction against every external writer. The SSH FileSystem implements that exact limited operation with one fixed, one-shot Python stdlib program: POSIX flock on the same sidecar, complete streaming content hash under the lock, unique owned sibling temporary file, original permission preservation, file fsync, atomic replace, parent fsync, then unlock. A conflict returns false without replacing the target; an error can occur after replacement and remains a possible effect. The sidecar is never unlinked, and a foreign temporary collision is never cleaned up as ours.

The fixed code is passed to the original executor; path, expected digest and base64 replacement bytes use bounded structured stdin. No code is installed on the server, no daemon or new agent tool is created, and input/exception messages are not logged. Isolated Python uses only standard primitives. A read-only probe through the same connection checks availability, and the actual helper checks again; missing primitives remain explicitly unsupported. Probe success alone does not qualify that server/filesystem. Cancellation or a lost SSH result does not automatically replay the write or report rollback.

The standard FileSystem.open_read returns a reader over the actual SFTP file handle. Each read requests at most 64 KiB, independent of artifact size; it does not preload the file or require Python. The original CompletionGate/hash algorithm consumes that reader. Read failure stops the stream instead of replaying an offset, and success does not return EOF before the original file, client tasks, child and pipe settle. Ordinary file requests and this reader share one original channel launch/settlement path; early drop uses the same blocking caller and connection guard, with no new runtime, thread or owner.

Standard SFTP attributes do not expose the stable dev/inode and no-follow held-directory identity needed by the original directory guard. This provider therefore keeps that separate capability unsupported; a guarded lifecycle mutation must reject before effects instead of substituting mode/mtime/realpath. File read/list/Git and CAS are not evidence that directory-identity protection has been qualified.

The exact helper passed 13 local native fixtures, including competing processes, a different cooperating writer, full-content/tail comparison, binary/Unicode data, permissions and errors after rename/fsync/unlock. Deliberately removing the lock or hashing only the first chunk each produced the expected assertion failure. These were self-owned local temporary files: Cargo/Rust tests, live SFTP, remote Python primitives, GUI writes and the real server remain separately unqualified. The native fixture is also wired into the app-core test chain for later execution. Existing examples and SDK accepted contracts have no new CAS consumer; website synchronization follows qualified integration, without deployment.

References: [Python flock](https://docs.python.org/3/library/fcntl.html#fcntl.flock), [Python atomic replacement](https://docs.python.org/3/library/os.html#os.replace), [Python fsync](https://docs.python.org/3/library/os.html#os.fsync). Locked fs2's Unix implementation uses the same flock/LOCK_EX and LOCK_UN primitives; the original core helper remains the local authority.

The source initially targets Unix OpenSSH multiplexing. Other platforms, actual compilation, dependency-risk qualification and real GUI/password/remote-project acceptance require separate evidence. No source-only test definition or the old terminal binary qualifies this workflow. Existing examples have no project-SSH consumer; product documentation and the website must be synchronized from the qualified integrated source, without deployment. The SDK public/accepted contract is unchanged.

References: [OpenSSH multiplexing configuration](https://man.openbsd.org/ssh_config.5#ControlMaster), [standard SFTP client](https://github.com/openssh-rust/openssh-sftp-client/tree/ad1b77f1d7b35fc39183bae9d68034e3d9f9e8e6), [published 0.15.10](https://crates.io/crates/openssh-sftp-client/0.15.10). Original official responses and source bytes are retained with the engineering evidence.

## Remote completion knowledge and existing bounded observers

SandboxExecutor.execute remains the original physical-settlement future. Its command deadline/cancel requests do not create a bounded-return promise at this trait boundary or prove remote termination. Actual TaskRun/command-cell owners keep their existing bounded nonterminal observation. Direct GUI file/Git/CAS work uses the original ProductDataIoService bounded observer in the integrated application: its deadline limits only the caller's wait, while the same admitted I/O operation, blocking closure, host lifetime and permit continue. No backend fabricates a TaskRun identity, normal cancellation receipt or second supervisor.

After an actual command/subsystem child starts, the same ProjectSshConnection retained_children container synchronously retains its original operation, invocation guards and immutable effective target before the next await. Losing the physical observer cannot drop that projection. Known completion removes the same entry and releases its resources; the container does not grow with already-completed commands. Local-child retry remains separate from remote-stop knowledge and cannot clear a remote obligation using local EOF/wait, master check, reconnection, elapsed time or a changed alias. Existing cleanup only re-observes these same resources.

A native SSH255 or missing exit status after a command may have started means that the remote-stop receipt is unavailable. The original invocation waits on its connection's progress and keeps its guards/master obligation; it does not return ordinary Possible error and become a fake completed Cell. This transport currently has no recoverable remote command identity or lost-exit replay. Therefore a genuine disconnected remote obligation has no automatic settlement event. It remains honestly retained, without a daemon, process store, guessed PID/kill, manual receipt console or acknowledgement bypass. A real non255 command exit plus required local joins is a completion proof even when the command returned125..127, a structured CAS reply reports a post-replace error, or contents/side effects still need verification. Those Possible effects do not cause indefinite physical retention.

The thin standard SFTP client adapter preserves whether a native mutating request returned a server response or lost it before mapping to ToolFailure. Standard Sftp.close actually waits for buffered/sent request responses. A missing mutation response without that close proof remains with the same connection and nonterminal future; a completed request with uncertain file contents releases normally. No terminal local child result alone substitutes for an outstanding write acknowledgement, and no failed mutation is replayed.

The v4 regressions use the same production launch/wait/resource path with self-owned local fixture processes for255, missing status, observer loss, actual known completion, and deadline/cancel observation. They are source definitions only in this slice. Neither they nor earlier native CAS fixtures qualify Rust compilation, the integrated ProductDataIO/TaskRun/Cell route, real SFTP, a remote server, or automatic reconnect recovery. Examples and website claims remain for the qualified integrated project delivery.

The SFTP error adapter treats current-request mutation-response knowledge separately from effects already completed by the containing operation. Recursive delete and parent creation retain a local completed-mutation flag, including parent creation before atomic-write metadata lookup. A later readonly failure preserves PartialSideEffect/Possible/VerifyThenRetry when an earlier mutation completed, without inventing an outstanding-write stop obligation. With no completed mutation, the readonly failure keeps its ordinary no-effect classification. The paired controlled local fixture tests remain uncompiled source definitions, not a real SFTP/server claim.
