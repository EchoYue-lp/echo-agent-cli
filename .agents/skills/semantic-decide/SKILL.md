# EKO 语义裁决

主 Agent 负责搜索、追踪和取证；用户只处理无法由源码、契约或测试推导的产品选择。每次只提出一个明确问题。
写回前调用 `semantic-contract`，确认目标对象、状态和引用字段；没有具体目标对象时不得创建裁决记录。

## 裁决内容

展示重要承诺、当前行为、已有期望/冲突、关键证据、受影响的 TaskRun/PlanTask/SubagentRun 或交互端，
以及唯一待决定的问题。可选结果是确认期望、修正期望、接受风险或暂缓并补充信息。

确认或修正时写回原行为承诺/规则；`risk_accepted` 必须保留人的明确裁决。人确认的期望受保护，后续差异可以
让实现变为 `stale`，但不能把相反实现自动解释成新预期。不要替用户决定公共契约、架构、兼容性或是否删除能力。

裁决写回后调用 `semantic-verify`；若裁决要求修改代码，回到正常设计/计划/构建流程，代码形成差异后再调用
`semantic-diff`。
